# VoteLab 0.4.5 重复启动问题

## 已确认的问题

组员在 Mac 重复打开应用后，终端显示 `OSError: [Errno 48] Address already in use`。随后访问 http://127.0.0.1:8765/ 能看到 VoteLab，说明旧服务已经在运行。它不属于下载页失效。关闭浏览器页面不会停止本地服务器。

## 处理

| 情况 | 0.4.5 行为 |
| --- | --- |
| 同一数据目录已有新版运行 | 先核对本地实例身份，再打开该实例的同一网页地址；不重复备份或迁移数据库。 |
| 两个新版同时启动 | 通过操作系统文件锁确定一个拥有者，其余启动器等待实例就绪后复用。 |
| 程序异常结束后重启 | 操作系统释放锁；新进程覆盖过期实例状态，继续读取原数据库并按既有规则备份。 |
| 请求端口被其他或无法识别的旧服务占用 | 在数据库备份和迁移前显示明确错误；不自动停止进程或切换端口启动第二个服务。 |
| 启动时没有可见终端 | 启动信息和 Python 阶段错误仍写入 launcher.log；Mac 打包程序显示启动失败提示。 |
| Windows 端口占用 | 使用独占绑定，避免两个 HTTP 服务意外复用同一端口。 |

身份校验使用每次启动生成的本地令牌，配合实例记录核对。仅根据网页标题不能可靠确认服务身份。令牌和运行状态不属于账号或投票记录。

## 升级和数据

旧版 0.4.4 没有新版身份接口或同一文件锁，不能假定它可以自动参与新版实例复用。升级前先在 Mac 活动监视器中退出已知旧 VoteLab。Windows 在原窗口按 Ctrl+C。无法确定占用者时先打开 http://127.0.0.1:8765/ 核对内容，不任意结束其他进程。

数据位置沿用原设置：Windows 为 `%LOCALAPPDATA%/VoteLab`，Mac 为 `~/Library/Application Support/VoteLab`。保留 `voting.sqlite3` 和 `backups`。同一电脑升级使用原数据目录；不同电脑的本地包仍各自存储资料，本版没有增加云端共享。

## 验证范围

发布前需验证完整回归套件，以及重复启动、不同请求端口仍复用同一数据目录、崩溃后的锁释放与数据保留、陌生端口占用时数据库不变、本地身份接口校验和无终端日志等场景。

Windows、Mac Apple Silicon 和 Mac Intel 运行包还需从实际 ZIP 解压后检查启动、重复启动和重启持久化。构建检查使用 macOS 15；不据此宣称已在 macOS 14.5 或 Finder 双击流程中完成验证，也不宣称获得 Apple Developer ID 签名、公证或生产环境认证。最终通过项数和发布结果由构建记录确认。

若 macOS 在 Python 启动之前拦截程序或运行库加载失败，launcher.log 仍可能尚未生成；这与进入 Python 后的启动错误需要分别排查。
