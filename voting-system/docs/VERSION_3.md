# Version 3 / 第三版

## 用户发现与本轮范围（2026-11-02）

用户实际使用创建页后发现：只能输入名称，无法完成“上传不同奶龙照片、填写名字和介绍，再比较投票”的场景。用户随后明确要求本轮加入参赛者报名上传及创建者审核，并通过截图提出语言、登录、身份和截止日期改进。

本轮已实现：

- 创建者逐项添加、移除、修改图片/名称/介绍，保存、预览后再开启报名或投票。普通选项图片和介绍可选，避免限制纯文字投票；参赛者报名必须带图片。
- 实际图片经Pillow校验、去元数据、重编码为JPEG，储存在各自SQLite数据库中，不是只在浏览器预览。PNG/JPEG/WebP、每张5MB/1600万像素、总请求24MB；前端也提示格式和大小。
- 普通账号可在征集中的活动提交一份作品，状态为待审核；创建者通过/驳回，驳回须有原因。反馈出现在“我的作品”。通过前正文和图片不向其他访客公开。
- 创作者不能把参赛者原稿偷偷改写成自己的内容；其作品在审核页管理。
- 至少2项已通过、没有待审作品才可开票；开票关闭报名并锁定规则、名单和图片。
- 同一手机号可创建、参赛、投票。所有登录只用验证码，不再要求密码或重复手机号输入。账号不分固定MANAGER/VOTER，管理权限取决于活动creator_id；旧role/password列保留兼容，但不用于登录或提权。
- 界面支持中文/英文，cookie保存选择；用户作品、名称和介绍不自动翻译。
- 注册入口增大；常用模板预设单选/评分与是否征集，不生成假作品。
- 分钟时长改为具体年月日和时间，明确UTC+8。发布开启即开始投票，定时开始仍未实现。

## 需要组内确认的实现上限

当前截止时间须在1分钟后、30天内。30天是可调整的原型配置MAX_DAYS，不是已确认业务需求。每活动20项、每账号每活动一份报名作品、介绍1000字、图片限制也是本轮可复核实现边界，不声称客户已逐项同意。

## 当前限制

验证码仍是本地模拟，在页面显示，不是真实短信或手机号归属证明。新注册无需密码；旧演示密码不再可用于登录。

报名作品暂不支持参赛者自行修改、撤回或驳回后重新提交；创建者可在开票前重新审核。全站管理员、双人审批、延期、奖项自动分配、平票加赛、PDF导出、多选、决选、真实身份核验与永久部署仍未完成。

## 设计与验证

需求变化对应：图片BLOB表images；候选项description/image_id/submitter_id/review_status/review_reason；活动planned_end/allow_submissions/submissions_open。保留旧用户、活动和选票，启动时增量迁移；更改前分别备份本地与共享数据库。

27项自动测试通过，覆盖图片有效/非法/超限、事务回滚、防止图片越权、草稿编辑保留/更换/移除图片、显式开放报名、重复报名、驳回反馈、审核到投票、开票锁定、统一账号权限、验证码、语言、截止与旧的选票规则。

浏览器检查：本地验证码登录；创建两项图片名称介绍、实际文件选择与上传、保存预览；中文切英文再切回；开放报名；另一个账号提交作品并看到待审反馈；创建者填写反馈并通过审核，界面显示已通过。开票锁定及投票数据由自动测试覆盖，本轮浏览器未重复测试全部选票路径。

## 软件工程证据链

用户场景发现缺口 → 本轮明确图片/报名/审核范围 → 更新数据、页面和流程 → 代码实现 → 自动化及浏览器验证 → 分享给组员继续寻找问题。

本轮通过本地测试不等于小组最终验收，待收集组员反馈后再排序、修改和复测。
